\section{Reproducibility materials}

The corrected release stores the source snapshot, arguments, input hashes, package versions, and model-level result files. It includes dated predictions, persistence forecasts, and the table and figure sources. The original local batch retains the fitted checkpoints and feature scalers; the public reproduction scripts regenerate these objects. Complete experiment keys identify the dataset, ticker, price mode, horizon, feature set, implementation, window, and seed where applicable. The boundary export records actual dates and sample counts for each condition rather than using one ticker to represent an entire dataset. These files support inspection of both the reported results and their evaluation scope.

The earlier technical-feature branch references persistence errors from a different test period. Direct tracing of the unchanged archived functions identifies this mismatch in 990 conditions, affecting 17,820 supervised rows. The corrected implementation recomputes persistence on each model's test origins and removes training and validation labels that cross the next segment boundary. We retain the original archive separately and use the complete corrected batch for the revised tables. Because the rerun includes other corrections and runtime differences, we do not attribute all numerical changes to the baseline repair.

The completed batch contains 35,640 supervised rows, 990 sampled-origin Chronos rows, and 60 full-origin subset rows. Verification reconstructs the declared test origins, matches their targets to the input data, and recomputes the three errors, ratios, and gates. Additional checks independently reconstruct all 1,980 supervised split conditions and reconcile the aggregate tables. Inference replay covers 72 stratified checkpoints; this is not a replay or independent retraining of every model. The supplementary material documents these checks and their limits.

The manifests record Python 3.13.3 and PyTorch 2.11.0 with CUDA 12.8 for this batch. Chronos uses the fixed model revision recorded in those manifests rather than an unversioned download. The files retain the original source key \texttt{dlinear} for traceability, while the revised manuscript calls that implementation a linear temporal proxy. These records identify the corrected batch without claiming identical behavior in every software or hardware environment.
