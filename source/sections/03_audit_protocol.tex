\section{Audit protocol}

The audit compares future closing-price forecasts with latest-close persistence. The protocol specifies data preparation, time splits, model fitting, and evaluation. Each corrected model--baseline comparison uses identical test origins and target dates. The subsections below describe these steps and distinguish the supervised and zero-shot protocols.

\subsection{Data collection}

The audit uses a fixed snapshot of daily Yahoo Finance data spanning 02-01-2015 to 30-04-2026. Table~\ref{tab:dataset_coverage} summarizes the five configured asset lists. The download summary contains 165 asset entries and 133 unique ticker symbols because several stocks appear in more than one list. One configured Hong Kong ticker has no successful download and does not enter the analysis. The overall date range does not imply that every asset has a complete record throughout this period.

\input{tables/crossmarket_dataset_coverage}

The inputs contain open, high, low, close, and volume (OHLCV). Raw-close experiments use the downloaded fields directly, while adjusted-close experiments multiply OHLC prices by the downloaded adjusted-close to close ratio and retain the volume field. The target is the closing price 1, 5, or 10 trading days after the forecast origin. Each origin represents the point after observing that day's close, and each horizon uses a separate direct forecast. These experiments evaluate price levels, not returns, directions, volatility, or trading profit.

\subsection{Time splits and persistence}

For each asset, price mode, horizon, and feature set, we first remove rows with missing required features or targets. We divide the remaining observations chronologically into 72\% training, 8\% validation, and 20\% testing. We then remove training and validation examples whose target dates reach or pass the first origin of the next segment. These percentages describe the split rule before this boundary removal. Indicator warmup and differences in available records mean that feature sets and assets can have different evaluation dates.

We fit feature min--max scalers using feature rows before the cut between training and validation. Training-target normalization uses only the retained training labels. Validation loss selects the checkpoint, and test errors do not guide checkpoint selection. At each test origin, the fitted model uses its available input window without another training update. The exact boundary file records the dates and retained sample counts for all 1,980 asset--price--horizon--feature conditions.

Latest-close persistence predicts the future closing price with the close at the forecast origin. This is the naive forecasting rule applied to the price-level target \cite{hyndman2018forecasting}. We compute each model's baseline errors on exactly the same test origins and target dates as its forecasts. This alignment ensures that their reported errors describe the same test cases. It does not make different feature sets or forecasting protocols a common-date model comparison.

\subsection{Supervised implementations}

The supervised experiments cover LSTM, GRU, a linear temporal proxy, and compact PatchTST-style, iTransformer-style, and TimeMixer-style implementations. Table~\ref{tab:model_implementations} describes their main components. The linear proxy has no trend and remainder decomposition and therefore does not implement the published DLinear architecture. The three modern style implementations also differ from the official full systems. Our results concern these selected implementations rather than rankings of the published architectures.

Each model uses a 60-trading-day input window. The two feature sets are OHLCV and OHLCV with relative strength index (RSI), moving average convergence divergence (MACD), and Bollinger-band indicators. Recurrent and transformer representations have dimension 64, while the TimeMixer-style hidden layers have widths 128 and 64. The nonlinear implementations use dropout 0.1, and the transformer and mixing components use Gaussian error linear unit activations. The full grid contains 5,940 configuration--seed rows per implementation, or 35,640 supervised rows in total.

Training uses AdamW with learning rate 0.001, zero weight decay, batch size 128, and gradient clipping at norm 1. We allow at most 80 epochs and stop after eight epochs without a validation-loss improvement greater than $10^{-5}$. We retain the best validation checkpoint and use seeds 42, 123, and 777. Training batches shuffle within the training segment; validation and test observations retain chronological order. Each fitted model then predicts all eligible test origins without refitting.

\subsection{Chronos evaluation}

The zero-shot experiments use Chronos-T5-small without fitting it to the study assets. Each forecast uses a univariate close-price context of up to 512 observations and 20 generated sample paths. The point forecast uses the lower middle value among the 20 samples at the requested horizon. The main protocol selects up to 96 evenly spaced indices from each chronological test segment, producing 990 asset--price--horizon rows. The implementation fixes the model revision and derives a reproducible generation seed from base seed 42 and the experiment key.

A supplementary check uses every eligible test origin for the first two assets in each configured list. It covers both price modes and all three horizons, giving 60 rows from 10 asset entries but nine unique tickers. This small, non-random subset provides a limited sensitivity check. The sampled and full-origin runs generate forecasts separately, so their differences do not isolate the effect of origin selection alone. Chronos also differs from the supervised protocol in context length, input variables, and test-origin coverage, so we report the protocols separately.

\subsection{Errors and descriptive summaries}

For $n$ target prices $y_i$ and forecasts $\hat y_i$, we record RMSE, mean absolute error (MAE), and mean absolute percentage error (MAPE):
\begin{align}
\mathrm{RMSE} &= \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat y_i)^2}, \\
\mathrm{MAE} &= \frac{1}{n}\sum_{i=1}^{n}|y_i-\hat y_i|, \\
\mathrm{MAPE} &= \frac{100}{n}\sum_{i=1}^{n}\frac{|y_i-\hat y_i|}{\max(|y_i|,10^{-8})}.
\end{align}
The RMSE gate requires the model-to-persistence RMSE ratio to be strictly below one. Equality does not pass, and a separate all-three count requires lower RMSE, MAE, and MAPE. Model summaries report counts, rates, medians, and descriptive distributions of the fixed experiment grid. Repeated tickers, price modes, horizons, feature sets, and seeds create dependent rows, so these rows are not independent trials. We therefore do not report row-independent confidence intervals or significance tests.
